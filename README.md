# 微读 · 每日阅读助手

单账号微信读书网页版自动化 MVP：官方扫码登录、会话保留、每日定时阅读、手动运行与停止、SQLite 历史记录、可配置的官方页面字段核验和签到适配。

**推荐部署：GitHub Actions。** 启用定时任务后每天北京时间 09:17 运行，也可手动触发；本地管理页面是可选调试工具，Actions 运行不需要管理口令。

**当前没有真实账号的计时或签到成功验证。** 默认只执行网页阅读，结果标记为“待确认”；运行五分钟、请求被接受和官方计入五分钟是不同结果。签到入口因活动而异，须先核实活动支持网页版，才能填写适配配置。

2026-10-19 已完成[真实账号扫码与阅读实测](https://github.com/GeneElias/WechatRead/actions/runs/39187096267)：飞书卡片展示二维码，官方扫码登录后运行阅读 360 秒，12 次阅读请求均被服务器接受。[独立只读复核](https://github.com/GeneElias/WechatRead/actions/runs/39187930101)确认新的运行环境能恢复加密会话并通过登录验证。官方今日阅读时长仍未取得，签到活动尚未配置；这些结果不代表官方计时或签到已完成。

## GitHub Actions 部署

### 1. 连接飞书群机器人

在你的飞书群中添加自定义机器人，在 GitHub 仓库 Settings → Secrets and variables → Actions 中配置：

| Secret | 用途 |
| --- | --- |
| `FEISHU_WEBHOOK_URL` | 必填，自定义机器人的 HTTPS Webhook 地址 |
| `FEISHU_SIGN_SECRET` | 若开启机器人签名校验则必填，否则不填 |

如果开启关键词校验，请允许“微信读书”。机器人需要能发送消息到你可接收的群。不要把 Webhook 或签名密钥粘贴到聊天、配置文件或提交记录中。

### 2. 从飞书完成远程登录

不需要本机安装程序或导出 Cookie。在 Actions 运行“飞书扫码实测”或“每日微信读书”。缺少有效登录态时，程序打开官方登录页、解码二维码并发到飞书。若官网提供二维码图片链接，则发送“打开官方二维码”按钮；若只有内嵌图片，则通过飞书原生图表组件在卡片里绘制可扫码二维码。二维码数据只发送到已配置的飞书机器人，不上传公开附件或第三方图床。

收到通知后，用微信扫描卡片里的二维码并完成官方确认；在同一部手机上可先放大并截图，再从微信扫一扫的相册入口识别。官方登录确认链接仅作为备用入口，打开该链接不等于显示二维码。程序最多等待十分钟，期间适时刷新并发送新的二维码，最多六条；确认成功后自动保存加密会话、选书并继续阅读。原生二维码组件的终端显示和扫码仍需真实客户端验证；本地已验证飞书支持的 VChart 1.12.3 渲染结果可被二维码识别器解码。

未指定书籍时，自动选择官方网页书架中的第一个阅读器链接；书架为空或页面没有对应链接则失败并通知。可选仓库变量 `WEREAD_BOOK_URL` 指定已有阅读权限的书籍。程序不购买书籍或报名付费活动。

加密密钥默认通过 Webhook 内的高熵令牌与固定用途标识派生，不需要手动设置会话 Secrets；更换 Webhook 后会自动重新扫码。也支持可选 `WEREAD_SESSION_KEY` 指定独立 Fernet 密钥和 `WEREAD_INITIAL_STATE` 导入历史加密登录态，但新流程不要求这两项。登录态只存入加密的 Actions 缓存；缓存被淘汰或登录失效时重新通过飞书确认。

### 3. 每日调度与手动运行

在仓库 Actions 中选择“每日微信读书”→ Run workflow，使用 `main` 分支。完成飞书扫码后，程序会将运行结果发回飞书，同时在 Actions 摘要及附件中保留结果。机器人请求失败、签名错误或关键词不匹配时，任务会明确失败，不会假装已经发出通知。

每日调度已默认开启。若之前设置过停用变量，可重新启用：

```bash
gh variable set WEREAD_ENABLED -R GeneElias/WechatRead --body true
```

未设置 `WEREAD_ENABLED` 或其值为 `true` 时，定时任务执行；设为 `false` 可停用，其他非空值也会跳过。手动触发仍可用。默认每天北京时间 **09:17（UTC 01:17）**，修改 `.github/workflows/daily-read.yml` 的 Cron 可调整。`config/actions.json` 设置目标时长、统计字段和签到适配；仓库变量 `WEREAD_BOOK_URL` 覆盖文件中的书籍链接。GitHub 工作流不会使用本地管理页面保存的计划，也不会托管常驻网页，GitHub Pages 无法运行本程序。

**结果解释：** Actions 绿色只表示程序完成执行。是否计时、是否签到，应分别看摘要的“阅读核验”和“签到核验”；没有统计适配时是“待确认”，不是官方达标。工作流执行失败则显示红色。认证、配置或浏览器失败不会被当作成功。当前没有默认猜测的签到入口。

“会话与阅读证据复核”工作流会在新运行环境中恢复加密缓存、验证登录，并读取最近成功实测的请求计数；它不重复执行阅读。服务器接受阅读请求仅是辅助证据，不能直接折算成官方分钟数。只在页面存在明确的今日阅读字段时读取当日时长。

GitHub 调度可能延迟，不提供严格准点或补跑保证；定时工作流仅在默认分支生效，公开仓库长期无活动时还可能被平台停用。同一仓库的账号任务串行运行，不开启 PR 触发的账号任务。“飞书扫码实测”在其工作流文件推送到 main 时触发一次，也支持手动触发；没有配置机器人时会在预检处停止。结果附件保留 14 天，不含二维码链接、浏览器 profile、Cookie 或加密密钥。建议使用私人仓库管理个人账号任务；公开仓库中不要提交包含个人信息的配置或运行结果。

手动运行与每日运行均为独立任务，多次手动触发可能重复阅读。仅 GitHub Actions 的并发控制负责串行化，不提供跨工作流、跨仓库的账号锁。若需停用，设置 `WEREAD_ENABLED=false` 或在 Actions 中禁用工作流。

### 4. 飞书每日状态报告与手动查询

“飞书项目状态日报”每天北京时间 **18:00（UTC 10:00）** 向现有机器人推送一次报告，独立于阅读开关。首次部署该工作流也会推送一次，无需新增 Secrets。阅读未开启、被跳过、失败、超时或正在排队时，均会显示对应状态；若停用该日报工作流，就不再推送日报。

报告显示每日阅读开关、GitHub 工作流是否启用、最近触发时间与状态，以及最近结束且未跳过任务的阅读请求计数、阅读核验和签到核验。只查询两个阅读工作流最近各 30 次触发；历史任务明确标注日期，不当作今日结果。结果附件过期、缺失或读取失败会明确提示。报告只读取 GitHub 元数据和结果附件，不访问账号、不触发阅读，也不证明当前登录态有效。GitHub 调度可能延迟或被平台停用，无法保证每天准时送达。

需要随时查询时，点击飞书卡片的“手动查询 / 更新报告”，在 GitHub 页面选择 **Run workflow**（需仓库权限），随后报告会发送到飞书。也可执行：

```bash
gh workflow run status-report.yml -R GeneElias/WechatRead --ref main
```

当前使用的飞书自定义 Webhook 机器人仅负责推送，不能接收你在群中发送的“查询状态”消息。若需要直接在飞书对话里查询，须另行配置飞书应用机器人、消息事件订阅及常驻接收服务；仅部署 GitHub Actions 无法接收这类消息。现有阅读任务执行结束后的结果通知仍保留，日报用于补充跳过、提前失败等情况。

## 本地启动

需要 Python 3.12+。使用现有 checkout；不需要建立 Git worktree。

```bash
cd /workspace/WechatRead
python -m venv .venv
.venv/bin/pip install -r requirements.lock.txt
# 优先使用已安装的 chromium；没有时安装 Playwright 配套版本：
PLAYWRIGHT_BROWSERS_PATH="$PWD/.data/browsers" .venv/bin/python -m playwright install chromium
.venv/bin/python -m weread
```

也可执行 `bash scripts/setup.sh` 安装锁定依赖并测试，然后执行 `bash scripts/start.sh` 启动。`requirements.txt` 和 `requirements-dev.txt` 用于维护直接依赖，`requirements.lock.txt` 固定本次验证的完整依赖版本。

若系统已有 `chromium`，可跳过浏览器下载。也可用 `WEREAD_CHROMIUM` 指定兼容的可执行文件。Linux 机器须安装 Chromium 所需系统库；Playwright 提供 `playwright install-deps chromium`，需系统安装权限。

默认仅监听本机 8000 端口。首次启动在 `.data/admin-token` 生成管理口令，在本机读取该文件并输入管理页面；不要把它提交到仓库或发送到聊天。远程访问使用受保护的端口转发，或有 HTTPS 的反向代理；HTTPS 部署设置 `WEREAD_SECURE_COOKIE=1`。不建议直接暴露管理端口。单实例、单 Worker 运行，不要加多个 Uvicorn Worker。

可配置环境变量：`WEREAD_DATA_DIR`、`WEREAD_HOST`、`WEREAD_PORT`、`WEREAD_CHROMIUM`、`PLAYWRIGHT_BROWSERS_PATH`、`WEREAD_SECURE_COOKIE`。浏览器使用环境中已有的 HTTPS 代理（若有），保留 TLS 校验。

## 使用步骤

1. 进入管理页面，输入本地管理口令。
2. 点击“打开登录页”，扫描官方页面截图中的二维码，在微信完成确认；刷新截图检查状态。验证码和额外验证需要本人处理。当前不提供远程浏览器任意点击操作。
3. 在官方网页版打开一本有权限阅读的书，把 `/web/reader/` 链接填入计划并保存。
4. 手动运行一次，在官方客户端核对当日统计和目标活动结果。
5. 核验成功后开启每日定时。默认北京时间 09:00、当日目标 5 分钟、运行上限 8 分钟；任务加入最多一分钟余量。没有配置统计读取时，不会宣称官方达标。

任务每天运行依赖本服务和机器持续在线。当天错过时间时，服务恢复后补执行一次；不补跑以前日期。每个自然日最多创建一条定时任务，失败后须人工处理并手动重试；手动任务可用于重试。活动“超过五分钟”的具体门槛须以当前规则为准。

## 官方结果配置

高级配置的“统计页面”和“CSS 选择器”必须一起填写。选择器须唯一匹配**当日阅读时长数值**，支持 `5分钟30秒`、`1小时2分钟`、`05:30`、`01:02:03`。无法确定字段含义时留空。每日累计模式检查末值是否达到目标；新增模式比较任务前后差值。期间不要用其他设备阅读，否则不能将差值归因于本任务。跨日时一律标记待确认。

签到适配需填写官方活动 URL、唯一的按钮完整文字和唯一的成功状态完整文字。系统在官方页面点击按钮后观察成功文字；这只证明配置的页面标志出现，不证明奖励到账。不要将“领取”“购买”或付费活动报名配置成签到按钮。若该活动没有网页版入口，保持未配置。

阅读采用正常的 PageDown 操作，不复刻私有签名、不自行上报阅读时长。页面适配、书籍末尾和付费章节可能导致阅读停滞；本地计时并不证明内容推进，需结合官方结果判断。统计同步最多查询三次，仍未知时保留待确认。任务中断或服务重启不自动宣称成功。

## 测试

```bash
.venv/bin/python -m pytest -q
```

覆盖鉴权、配置校验、任务结果、调度去重、取消、重启恢复，以及真实 Chromium 对拦截测试页面的翻页、统计读取和签到状态变化。浏览器测试使用虚构会话和本地路由，不登录或修改真实账号。真实网站的可用性、最新活动规则和账号计时仍需单独验收。

## 数据与运行边界

`.data/` 包含浏览器会话、管理口令和数据库，已被 Git 忽略。请保护整个目录。浏览器状态可能包含登录凭证；不上传公共存储。退出管理页不退出微信读书，清除本地登录态会移除浏览器 profile；撤销远程设备请在官方客户端操作。

当前版本支持飞书通知，但没有自动提取官方统计选择器或长期运行保证。健康检查 `/health` 只表示管理服务可用，不表示官网可访问。当前 Codex 环境对官网的访问尚未放通，不能作为已经验证的每日托管服务。
